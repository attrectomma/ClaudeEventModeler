# Codegen session

`tools/codegen.mjs` has already written everything the model determines. **Your job is the holes it
left**, each marked `TODO(codegen)`: how a fold works, what a business rule actually checks, how a
projection groups, and the concrete values a test needs.

One slice, all the way down, until `dotnet test` is green. Not one layer across many slices.

## Before anything else

1. **`node tools/model.mjs validate diagrams/<system>/` must be at zero errors.** Implementing
   against a model that has not passed its own gate is building on a guess.
2. **`node tools/docs.mjs status` must show all three libraries mirrored.** If not, `sync` first.
   This is not optional and not a formality — see §2.
3. **Pick the slice with the furthest `status=`.** `ready` if one exists. Then set it to
   `in-progress` and **work on its own branch**: `status` is advisory, a branch is the only real
   exclusion git offers.
4. **Regenerate:** `node tools/codegen.mjs diagrams/<system>/`. It reports `N written, M kept` —
   `kept` files are hand-owned and will not be clobbered.

## 1. Only two kinds of file, and never edit the wrong one

| Banner | Meaning |
| --- | --- |
| `<auto-generated>` | derived from the model. **Editing is pointless** — the next run overwrites it. Change the model instead. |
| `<auto-generated-scaffold>` | written once, now **yours**. Regeneration keeps it. |

If you need something the model does not express, that is a signal about the *model*, not a licence
to edit a derived file.

## 2. Read the mirror. Then compile. The mirror is not enough on its own.

`reference/llms/<lib>/INDEX.md` is a local table of contents for each library. Read the pages you
need before writing — Wolverine and Marten move faster than model knowledge, so anything written
from memory is subtly wrong.

**And then verify by compiling**, because the docs are also wrong sometimes. Every one of these cost
real time on the first slice:

| Believed | Actually |
| --- | --- |
| `JasperFx.Resources` is a package | it is a namespace; the package reference fails restore |
| `JasperFxEnvironment` is in `JasperFx` | `JasperFx.CommandLine` |
| both projection base classes share a namespace | `Marten.Events.Aggregation.SingleStreamProjection`, `Marten.Events.Projections.MultiStreamProjection` |
| `IInitialData` in the DI container is picked up | only `.InitializeWith(...)` on the Marten chain attaches it |
| `FetchLatest` is on any session | `IDocumentSession.Events`, not `IQuerySession.Events` |

**When the docs and the compiler disagree, reflect.** A .NET 10 file-based app settles it in a
minute:

```csharp
#:package Marten@8.*
var asm = System.Reflection.Assembly.Load("Marten");
foreach (var t in asm.GetExportedTypes().Where(t => t.Name.Contains("Projection")))
    Console.WriteLine(t.FullName);
```

`dotnet run probe.cs` — no project, no restore ceremony.

## 3. The shape of a slice

**The endpoint is the decider.** It receives the folded state and returns events. So:

- **the state type** (`<Slice>State`) is a pure left fold — `Apply` and nothing else, no rules
- **the endpoint** holds every rule whose GWT `given=` names prior events
- **the validator** holds only the GWTs marked `enforce="periphery"`

**No `Create` methods.** A no-arg constructor lets any event open the stream, which matters because
"the first event drawn in the swimlane" is not a guarantee — see ANTI-PATTERNS.md #1.

**Fold every event of the stream, not just this slice's.** The daily cap needs the whole month, not
the booking being added.

**`[Aggregate]` does not fit a composite stream key.** It resolves a stream id from one route
argument. If `identity=` names more than one field, use `FetchForWriting<T>(streamKey)` — same
optimistic concurrency, same live fold, honest about the key.

**A cross-stream rule is a READ, never a second write.** One command, one stream: writing two would
need a transactional boundary around two aggregates, which `swimlane/command-crosses-swimlane`
forbids. Fold the smallest type that answers the question — not "the" other aggregate.

**Live on write, inline on read.** Nothing is registered for a state type; every read model is
`ProjectionLifecycle.Inline`, so a GWT's THEN is assertable the moment the request returns.

**A multi-stream projection with no `Identity<T>` rule is rejected at STARTUP.** That takes the whole
host down and turns per-test failures into identical fixture errors, destroying the signal. If a view
has no derivable grouping, leave its registration commented rather than breaking the host.

## 4. Rejections, and where the rule name lands

A rejected rule returns `ProblemDetails` with the rule's name as `Title`. But the two enforcement
points **do not produce the same shape**, and the front end must read both:

```
periphery (FluentValidation middleware) -> { errors: { Hours: ["HoursMustBeWholeOrHalf"] } }
the decider (your own ProblemDetails)   -> { title: "DailyCapExceeded", detail: "..." }
```

## 5. Test data is `IInitialData`, not invention

The model gives names and types and **never example values**. Seed the foreign/genesis events once
with fixed ids in a `SeedData : IInitialData`; `ResetAllMartenDataAsync()` re-applies it before each
test. Fixed ids make a failure reproducible and let a GIVEN name things.

A test's own GIVEN appends prior events **straight to the stream**, bypassing endpoints. A GIVEN is
history, not a sequence of requests to replay.

**Alba asserts the status code you set.** There is no "do not assert" value — `IgnoreStatusCode()` is
how you say it, and each test then checks its own.

## 6. The frontend is a port, not a design

`designs/<system>/<screen-slug>.html` already exists and has been reviewed. The React page **ports**
it: same markup, same class names, `tokens.css` used unedited, every `data-em` carried across so
`node tools/design.mjs check diagrams/<system>/` still holds the page to the model.

Do not redesign. If the design is wrong, that is a `styling` session.

**Show affordances the model says the screen has, disabled, for slices not yet built.** Hiding them
lies about the screen; enabling them lies about the app.

**`StreamOne`/`StreamMany` write Marten's raw JSON** and bypass ASP.NET's camelCase policy entirely,
so set `opts.UseSystemTextJsonForSerialization(EnumStorage.AsString, Casing.CamelCase)` or every read
endpoint quietly returns PascalCase and the client reads `undefined`.

## 7. Running it, and the two databases that must never meet

Tests use **Testcontainers**. The demo uses **docker-compose**. They never share a connection
string, and nothing in the test project reads the compose file. Marten manages schema, so a test run
pointed at the demo database drops the data you were halfway through creating.

```bash
docker compose up -d                                  # the human's Postgres, port 5433
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/<Sys>   # env VAR, not --environment
npm run dev --prefix web                              # Vite, proxying to the API
```

Three traps, all of which look like something else:

- **`dotnet run` swallows `--environment`.** Set the environment variable, or the app runs as
  Production and every Development-gated thing silently does not happen.
- **Postgres folds unquoted identifiers to lower case.** A camelCase database name in a connection
  string will not match what compose created.
- **Seeding is idempotent or it doubles.** `Populate` runs on every startup.

## 8. Close the loop by looking

The same rule the model has. **Screenshot the running page and read the image:**

```bash
node tools/design.mjs sheet designs/<system>/     # then read _shots/contact-sheet-*.png
```

For the live app, headless Chrome against the dev server. Always desktop *and* mobile — responsive
layout is where CSS silently fails, and on the first slice the desktop view was perfect while mobile
ran off the right edge.

## Gates

| | Must be true |
| --- | --- |
| Backend | `dotnet test` green. The slice's GWT tests are LIVE, not skipped |
| Reads | anything the screen `displays=` can actually be fetched |
| Frontend | `design.mjs check` clean, and you have **looked** at the screenshot |
| Model | `model.mjs validate` still at zero errors — implementing must not have needed a model change you failed to make |

Then promote the slice past `in-progress` and stop. **Do not start a second slice in the same
session**; the point of one-at-a-time is that the second one tells you what the first one cost.

## What a slice legitimately needs from its neighbours

A State Change slice is screen → command → event, and the screen reads a View another slice owns. So
finishing one slice end to end may require a **minimal read endpoint** belonging to a neighbour.

Add the minimum, mark clearly which slice it belongs to, and add no rules to it — so promoting that
slice later means adding its GWTs rather than undoing your work. Say plainly that you did it.
